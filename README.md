# تفسير HAI

تطبيق Android عربي بسيط جدًا لكتابة الرؤيا، ثم تحليلها على مراحل مع عداد حقيقي يمكن أن يتوقف لطلب معلومة مؤثرة قبل إكمال التأويل.

## ما تم بناؤه

- واجهة Jetpack Compose عربية RTL بهوية هادئة ومربع كتابة كبير وزر «تفسير» فقط تقريبًا.
- شاشة تحليل 0–100% مرتبطة بمراحل: قراءة، استخراج عناصر، سياق، تحقق، استرجاع معرفة، فرضيات، نقد، تصنيف، صياغة ومراجعة.
- توقف فعلي أثناء العداد إذا احتاج المحرك سؤالًا؛ يدعم خيارات جاهزة أو إجابة نصية ثم يكمل من نفس المرحلة.
- شاشة نتيجة تعرض التفسير، طبيعة المنام، القرائن المؤثرة، «لماذا هذا التفسير؟» والاحتمالات البديلة مع «والله أعلم».
- Backend بـ FastAPI حتى لا توضع مفاتيح AI داخل APK.
- Gemini كمسار أول عند وجود مفتاح، وOpenRouter كـ fallback. النموذج والمسار قابلان للتغيير من متغيرات البيئة.
- قاعدة معرفة SQLite/FTS5 مجانية، تفصل بين المصادر والحالات المفسرة وتسترجع **الموثق فقط** للموديل.
- لا تُحفظ الرؤى في جلسات دائمة افتراضيًا؛ طلب التفسير stateless ويعيد التطبيق إرسال الرؤيا والإجابات عند كل خطوة.
- fallback محلي داخل Android عند تعطل الخادم أو نفاد الحصة، ولا يخترع تفسيرًا تفصيليًا عند عدم توفر محرك موثوق.

## تشغيل Backend

من مجلد `server`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

أنشئ `.env` وضع واحدًا أو كلا المفتاحين:

```env
TAFSEER_GEMINI_API_KEY=...
TAFSEER_OPENROUTER_API_KEY=...
TAFSEER_PRIMARY_MODEL=gemini-3.8-flash
TAFSEER_OPENROUTER_MODEL=openrouter/free
TAFSEER_KNOWLEDGE_DB_PATH=knowledge/tafseer.db
TAFSEER_MAX_QUESTIONS=3
```

ثم:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

> ملاحظة خصوصية: شروط الاحتفاظ/التدريب تختلف بين المزوّد والخطة. لا تفترض أن المسار المجاني مناسب لبيانات شديدة الحساسية؛ راجع سياسة المزوّد عند النشر الفعلي.

## ربط Android بالخادم

ضع عنوان HTTPS للخادم في `gradle.properties` المحلي أو كـ Gradle property في CI:

```properties
TAFSEER_API_BASE_URL=https://your-api.example.com
```

إذا كان الحقل فارغًا، يعمل التطبيق بمحرك fallback المحلي. لا تضع مفاتيح Gemini/OpenRouter داخل تطبيق Android.

## قاعدة المعرفة الكبيرة

القاعدة مصممة لنوعين من السجلات:

1. `source`: مقتطف/قاعدة من مصدر معروف مع `source_title`, `source_ref`, `text`, و`verified`.
2. `case`: حالة تفسير سابقة تحتوي ملخص الرؤيا، السياق، التفسير، وملخص **سبب الترجيح**، وليس النتيجة فقط.

الهدف ليس بناء قاموس «ثعبان = عدو»، بل الاحتفاظ بالسياق والسبب الذي جعل معنى ما أرجح في حالة محددة.

الاستيراد عبر JSONL:

```bash
cd server
PYTHONPATH=. python scripts/import_knowledge.py knowledge/my_verified_data.jsonl
```

السجلات التي لا تحمل `"verified": true` يمكن حفظها للمراجعة لكنها لن تدخل في سياق النموذج.

## استراتيجية الجودة/التكلفة

- الاسترجاع من قاعدة المعرفة محلي ومجاني.
- سؤال توضيحي لا يُطلب إلا عندما يرى محرك السؤال أنه قد يغيّر التأويل.
- حد افتراضي 3 أسئلة حتى لا تتحول التجربة إلى استبيان.
- التأويل النهائي يستخدم سياق الرؤيا + الإجابات + المعرفة الموثقة ويطلب فرضيات بديلة ونقدًا قبل إخراج النتيجة.
- لا تُعرض سلسلة التفكير الداخلية؛ يظهر للمستخدم فقط ملخص القرائن القابل للتحقق.
- عند فشل جميع المزوّدات يمتنع النظام عن اختلاق تأويل تفصيلي.

## مبدأ المنتج

التطبيق لا يدعي كشف الغيب، ولا يجزم بأن المنام رؤيا صادقة أو بأن التأويل سيتحقق. لا ينبغي بناء قرارات طبية أو مالية أو قانونية أو اتهامات للأشخاص على نتيجة التأويل.
